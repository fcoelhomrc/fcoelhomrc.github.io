Checking the LLM judge before trusting it

Part 3 of 3. How to test an LLM judge against your own labels before using its scores, and what the tested judge said about each retriever.

September 25, 2026

Evaluating a RAG system, end to end

  1. Building a test set from your own papers
  2. Scoring retrieval without calling a model
  3. Checking the LLM judge before trusting it

Part 2 scored retrieval with gold chunk ids. Answers are harder: no id tells you whether an answer is true to its sources. For that, pipelines ask another LLM to grade the answer, called an LLM judge.

A judge is a model, and models make mistakes. This guide tests one judge against labels written by hand, before trusting any of its scores. The judge here, DeepSeek V4 Flash, passed: it agreed with the labels at Cohen’s kappa 0.83.

What the judge decides

The main judged metric is faithfulness: does the answer only say things its sources support? The evaluation library Ragas computes it in two stages.

  1. An LLM splits the answer into short statements.
  2. The judge reads the retrieved passages and each statement, and answers 1 if the passages support it and 0 if not.

Faithfulness is the share of statements marked 1. We test only stage 2, because that is where the judge decides. Stage 1 adds noise of its own that has nothing to do with the judge.

Step 1: Pick an agreement measure

The obvious measure is accuracy, the share of statements where judge and human agree. It flatters. In our test set 43% of statements are supported, so a judge that always answers 0 already scores 57%.

Cohen’s kappa fixes this. It compares the observed agreement with the agreement expected by chance, given how often each side says 1. Zero means no better than chance and 1 means perfect.

A study of 21 judges on the MT-Bench benchmark found that accuracy overstated kappa by 33.8 to 41.3 points. There, 85% accuracy meant a kappa of about 0.48 (Norman, Rivera and Hughes, 2026). We set the pass mark at kappa 0.6 before running anything.

Step 2: Write statements that target known failures

We need statements whose right answer we know. Each statement pairs a short passage with a claim, built to catch one way a judge can fail.

Here is one passage, kept as a test fixture in the project:

The policy recovers the robot from 94% of sampled fallen postures on flat ground within 3.2 seconds on average, compared with 61% for the scripted baseline.

Statements against it include “The policy recovers the robot from 84% of sampled fallen postures” (a wrong number, so 0). Against other passages, “Reinforcement learning agents learn from a reward signal” is true in general but not stated, so it is also 0.

Case type Statements It catches a judge that
Supported 29 rejects claims the passage makes
Paraphrase 11 wants the passage’s exact words
True but absent 8 checks whether a claim is true instead of whether the passage states it
Wrong entity 7 misses a swapped subject
Wrong number 6 misses a changed figure
Overgeneralised 6 misses a dropped condition
Unsupported cause 6 accepts a “because” the passage never gives
Unrelated 5 accepts text about something else
Negation 5 misses a reversed claim

Step 3: Label the statements blind

I wrote the 83 statements with an intended answer for each. To check those answers, I labelled every statement again on a page that hid both the intended answer and the case type. Two I could not decide, so I dropped them, leaving 81.

The blind labels matched my intended answers on 77 of 81 (95.1%). One of the four mismatches was “The policy recovers the robot from 94% of sampled fallen postures”. I had meant it as supported, but it drops “on flat ground”, and a dropped condition makes a claim unsupported.

When the two disagree, the blind label wins. Blind labelling exists to catch exactly these mistakes in my own construction.

Step 4: Run the judge and compare

The judge answered 1 or 0 for each of the 81 statements, with a prompt asking only whether the passage supports the statement. Agreement with the blind labels was kappa 0.828 and accuracy 0.914, well above the 0.6 pass mark.

Read the grid row by row. Of 35 supported statements, the judge accepted all 35. Of 46 unsupported statements, it rejected 39 and accepted 7.

Step 5: Read the errors

All seven errors go the same way: the judge accepted something the passage does not support. Three were “true but absent” statements, where the claim is correct in general but missing from the passage.

The other four were the four statements where my blind label overruled my intended answer, like the “flat ground” one. Without those four, kappa rises to 0.922 on 77 statements.

The judge never wrongly rejects, and sometimes wrongly accepts. Its faithfulness scores therefore lean high, and a score of 0.90 likely means a true figure somewhat below that.

Using the judge: answer quality by retriever

With the judge checked, we can grade real answers. For each retriever from part 2, Qwen3 30B answered all 100 questions from the top 10 chunks, and the judge scored four Ragas metrics.

Metric Question it answers
Faithfulness Does the answer only say what the retrieved chunks support?
Answer relevancy Does the answer address the question?
Context recall Do the retrieved chunks contain what the gold answer needs?
Context precision Are the useful chunks ranked near the top?

BM25 led on faithfulness (0.896), context recall (0.841) and context precision (0.693). It also never declined to answer, while each embedding model declined three or four times. One value is not comparable: bge-large’s answer relevancy was scored with an older judge setting.

These runs reuse the part 2 questions, so they inherit the same tilt toward keyword search.

Comparing the judge with the labels

Context recall and context precision measure retrieval, which part 2 measured with gold ids. Putting both side by side shows how far the judge drifts from the labels.

The judge reads higher on both: 0.841 against 0.797 for recall, and 0.693 against 0.626 for precision. Two causes fit, and this data cannot separate them.

  • The gold ids miss chunks that answer the question but were not its source, so labels score low.
  • The judge is lenient, as step 5 showed, so it scores high.

What it costs

Four judged runs of 100 questions cost $0.765 in total, about 19 cents each. The project notes estimate Claude Haiku 4.5 at about 15 times that for the same work.

Limits

  • 83 statements give a direction, with wide error bars on kappa.
  • One person labelled every statement, so there is no second human to compare with.
  • I wrote the statements, so they only test failures I thought of.
  • Only this one judge was tested. A comparison with other judges is designed and has not been run.
